# Provider fallback and recovery

`provider-fallback.json` controls equivalents/chains and provider limits. Provider limit marks live in `.provider-limits.json` beside the agent config. Automatic expiry restores the remembered original model unless `restoreWhenExpired` is false.

## Limit marks, manual choice and the status widget

- **Scopes.** A mark is keyed `"<provider>"` (account-wide: blocks every model of the provider) or `"<provider>/<model>"` (blocks that model only). A rate limit (`429`, `rate_limit_error`) marks the model that hit it, because provider rate limits are per model class. Text matching the defaults `usage limit`, `quota` or `billing|credit balance|extra usage|upgrade your plan`, or the optional per-provider `accountWidePatterns` (`{"anthropic": ["weekly cap"]}`, case-insensitive regexes; code defaults apply when the key is absent), marks the whole account. "Unavailable" (outage) marks stay provider-wide and short.
- **Old files.** Existing provider-wide entries keep working. One that stores a plain rate-limit error (429 / rate-limit text, no outage, quota or billing wording) naming a model of that provider now blocks only that model; every other legacy entry stays provider-wide. Entries are never rewritten.
- **A manual model choice is authoritative.** `/model` (or cycling) clears the marks that block the chosen model (the account mark, its own mark), forgets the remembered original, and pins the choice: it is not switched away pre-emptively, also not after `/reload` or when another session writes a mark. Only a real limit error from a request started after the choice moves the session again; an error from a request that started before the choice records the mark but does not switch. Only main (UI) sessions do this; subagents never clear shared marks. Other sessions that fallback moved may switch back and fail once if the provider is still limited.
- **Early expiry.** A successful request clears the account mark and that model's mark if they were written before the request started. Fresher marks (for instance from a parallel session) stay.
- **Shared file.** Every read-modify-write of `.provider-limits.json` (the extension and the `provider-restore` CLI) runs under an exclusive `.provider-limits.json.lock` file (stale after 10 s) and an atomic rename. If the lock cannot be taken (~2 s), clears, early expiry and restore deletes are skipped (the CLI exits 2 asking for a retry); only recording a new limit proceeds, as a merge that never removes other entries, and is logged. A stale lock is taken over by atomic rename. A manual pick also cancels any fallback switch queued or in flight (the user model is re-selected).
- **Status widget.** While fallback holds a session, a widget below the editor shows the model it is on, why, until when, and the undo commands (`/provider-restore <provider>` when loaded, always `provider-restore <provider>`). It also says when the extension files on disk changed since this session loaded them (`/reload` when idle). It clears on restore, manual selection and shutdown.

## Restoring from a busy session

`/provider-restore` is an extension command and runs at once, even while the session is streaming or compacting. It exists only in sessions that loaded the extension on or after 2026-10-25; in older sessions the text is sent to the model as chat. The `provider-restore [provider]` shell command is the reliable path for every session: it clears the marks and the sessions apply it at their next turn (including a busy session's next `turn_start`). `/reload` when idle loads the current extension. The widget's stale hint tells you when a reload is due.

After provider recovery, `/provider-restore [provider]` clears one provider's mark (or all marks when omitted) and immediately restores this session's remembered original, even with expiry restoration disabled. Add `--all` to broadcast to other running sessions. The stdlib-only `provider-restore [provider] [--all|--all-sessions]` CLI (the flags are aliases) clears the provider's account and model marks, always broadcasts, without restarting sessions. It honors `PI_PROVIDER_FALLBACK_STATE` and `PI_CODING_AGENT_DIR`.

Broadcast epochs live in `.provider-restore.json` beside the limit state. Other sessions consume them at the next turn/agent boundary. A main session whose last turn ended in a provider rate-limit error also watches the state directory while stalled: a debounced `fs.watch` notices restores/removal, with a 60-second fallback timer for expiry or missed events. Both are stopped when the stall is invalidated or the session shuts down. No watcher runs for normal turns.

`resumeAfterLimit` defaults to `true`. Once the failed provider's mark clears and `ctx.isIdle()` is true, recovery restores the original model under the usual restore policy, then sends one user message inside pi: "Provider limits have lifted (<provider>). Continue where you stopped." Set it to `false` to disable automatic re-prompting. Busy sessions are never re-prompted; a normal subsequent turn or fresh user input cancels the stalled episode. A fresh rate-limit failure starts a new episode. Unavailable errors do not trigger re-prompting.

Only sessions still on an extension-selected fallback with a remembered original restore; manual choices and sessions started on the fallback remain unchanged. A new real provider limit wins over an older restore request. Recovery does not disable future fallback. Automatic resume uses the existing context-budget role detection (current-process session status, otherwise UI = main and headless = subagent); subagents are excluded. Stalled markers are in memory only, so reloading does not re-prompt an old failure.

## Context allowance

- `maxContextTokensForFallback`: default `"auto"`. A number is an explicit token override; `0` disables this fallback context check.
- `fallbackContextRatio`: default `0.5`.

Auto allowance is `min(session handoff threshold, fallbackContextRatio × (TARGET contextWindow − TARGET maxTokens))`. Window and maximum output tokens come from the pi model registry, not the current model. For a main session, a 1.05M-window target normally caps at 400k; a 272k window with 128k output yields 72k. Subagents normally cap at 200k.

The role is read from the context-budget extension's current-process session status when available; otherwise UI sessions use main defaults and headless sessions use subagent defaults. Handoff thresholds are read from `context-budget.json` (`main.handoff`, `subagent.handoff`, and `models[CURRENT_MODEL][role].handoff`), honoring `PI_CONTEXT_BUDGET_CONFIG` and `PI_CONTEXT_BUDGET_STATE_DIR`. Missing config uses 400k/200k; missing target-window metadata uses the handoff cap.

Above the allowance, the notice gives the effective threshold and target and asks for `context_handoff` now (or `/compact`), ending the turn. The provider mark is retained. At the next prompt, fallback is attempted again against the reduced context; limits and other safety checks still apply. This does not turn off the context guard or compact destructively on the operator's behalf.
